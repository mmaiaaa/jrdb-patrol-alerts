To advance the sensing pipeline without accessing annotations, `scripts/cache_jrdb_dev_sensor_depth_candidates.py` uses only the **raw 2D detector cache**, **raw upper and lower LiDAR clouds**, and **the camera/LiDAR calibration** on four development frames. Lower points are transformed to the upper-LiDAR frame; both point sets are projected to each native camera, and each measured point receives an ego-frame horizontal XY radius from `upper2ego`. The script counts 0.5 m radial bands inside a fixed inner region of each raw detection. It records a nearest supported surface as a naive baseline, emits a dominant-band or single-band *surface candidate* when point support permits, and **abstains** on insufficient or similarly supported competing bands. Fixed exploratory thresholds are declared in the output JSON. It does **not** inspect native 2D labels, 3D labels, review decisions, annotated IDs or reference events.

These surface candidates are **not measured person distances**. Returns can belong to a wall, floor, another person, an occluder or a nonsynchronized cloud. No detector/range/alert metric can be reported from this cache alone. Follow up with an **offline, separate evaluator** that first matches detections to annotated people under a declared 2D criterion, checks independent human visual samples, reports errors in ego-frame XY range and abstention separately, and includes hard negative and crowded cases. Avoid using the reference to select a LiDAR cluster during sensing.

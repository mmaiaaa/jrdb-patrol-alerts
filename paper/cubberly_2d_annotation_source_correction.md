# JRDB 2022 native 2D annotation source correction

The `labels.zip` archive inspected on Cubberly contains **no** files in `labels/labels_2d/`. The earlier `scripts/inspect_jrdb_dev_native_2d_reference.py` assumed that folder existed; its `native_member_not_found` output correctly stopped before parsing or reporting an alignment score. Do not infer that the dataset lacks native 2D labels, and do not substitute head or panoptic annotations for full-body pedestrian boxes.

Five actual Cubberly members exist under `labels/labels_2d_activity_social/<sequence>_image{0,2,4,6,8}.json`. The [JRDB-Act paper](https://openaccess.thecvf.com/content/CVPR2022/papers/Ehsanpour_JRDB-Act_A_Large-Scale_Dataset_for_Spatio-Temporal_Action_Social_Group_and_CVPR_2022_paper.pdf) describes using JRDB annotated 2D boxes and track IDs in its action-labeling procedure, making this folder an **appropriate candidate for schema inspection**, not automatic proof of suitable box coverage, calibration or independence.

`scripts/inspect_jrdb_dev_activity_social_schema.py` reads exactly those five members on four Cubberly development frames. It reports actual JSON structure, annotation and `box` keys, example box structure and within-frame overlap of 2D and 3D pedestrian IDs, including IDs with evaluable 3D centers within the exploratory 3 m radius. The script reads neither detections nor test data. If its payload format is different from the expected `labels` mapping, it reports `missing_or_unexpected_schema` instead of fabricating a score.

After examining the schema and whether these files carry full-body boxes for the needed IDs, separately define an offline same-track 2D/3D reprojection comparison with explicit camera visibility, truncation, occlusion and timing caveats. No annotation may be used for online distance estimation or alerts. The sampled visual support for the ego-frame hypothesis remains qualitative until this check and additional representative-frame review are complete.

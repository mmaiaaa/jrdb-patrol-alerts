# Five-camera upper-LiDAR projection check

`scripts/audit_jrdb_five_camera_projection.py` is a **development-only visual diagnostic** for the full Cubberly raw-image cache. It reuses the existing compressed-PCD decoder and Brown-distortion projection from `scripts/audit_jrdb_cubberly_projection.py`. It loads `calibration/lidars.yaml` `sensor_0`, `sensor_2`, `sensor_4`, `sensor_6` and `sensor_8` individually; projects the matching **upper** point cloud into the native JPEG for each selected frame and camera; and draws the cached person boxes from `outputs/local/cubberly_native_full.jsonl` on top. It refuses a non-Cubberly/non-development manifest and does not load 3D reference labels or score events.

By default it checks frames `000087`, `000432`, `000864`, `001295`, covering the earlier view-coverage pilot and three later stages of robot motion. It writes 20 original-resolution PNG previews and a JSON manifest with source-file hashes, camera IDs, projected-point counts and box counts. Generated preview images belong in ignored `outputs/local/`, not the public Git repository.

Review a range of geometries in every camera: edges, doorways, walls, floors, visible person silhouettes and frame boundaries. For a suspected mismatch, open the original JPEG/PCD and adjacent frames; note camera ID and frame ID. A correct-looking cloud on a wall does not prove points on a nearby person are aligned. Exact camera/LiDAR acquisition offsets remain unknown. Color is **radial XY distance from the upper LiDAR**, not verified person distance. White rectangles are the detector's 2D boxes; multiple boxes can describe occluding people, duplicate boxes or backgrounds. Do not use point counts in a box as a person-range estimate or train/tune on the held-out test.

After visual projection checks, a separate measured-range method should associate foreground point clusters to detections, reject background and sparse/occluded observations, reconcile duplicate people across cameras, and quantify range and identity errors against development-only reference data. Keep this method separate from the reference event builder and document missing-sensor policies. Alert latency and false-alert rate require actual timestamps or explicitly frame-based exploratory reporting.
